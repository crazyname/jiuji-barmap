# 酒迹 · A「城市极简」UI/UX 规范（微信小程序开发版）

> 2026-10-17。**已确认视觉方向**：全局 A「城市极简」，参考 Google 地图类成熟地图工具的轻量信息组织；**品牌色仍为 `#82442F`**（原 C 主题棕红色），不得继承旧 A 的暗玫红 `#903F59`。
>
> **状态约定**：`[确认]` 用户已决定；`[建议]` 开发原型默认值，可修改；`[未定]` 不直接固化为上线规则。交互原型仅为示意，不表示项目已有对应页面或地图数据。
>
> 相关：[产品开发基线](product-baseline.md) / [微信开发路线](wechat-dev-roadmap.md) / [个人饮酒记录](personal-drinking-journal-design.md)。

## 1. 设计意图

**设计目标**：不像 PPT、杂志封面或 AI 生成的概念看板，而像每天用得顺手的地图与记录工具。优先回答「附近有哪些酒吧」「这家怎么样」「怎么去」「我喝过什么」「如何调这杯」。少装饰、多可见信息、明确按钮和返回路径。

**不要复制**：Google 的商标、地图瓦片、专有图标、地点数据、逐像素界面。仅借鉴搜索悬浮、地点选中、分级展开信息面板、列表与地图切换等通用交互。微信应采用合规可接入的地图底座并通过真机权限验证。

## 2. 设计 Token（开发目标，尚未改代码）

| Token | 目标值 | 用途 |
| --- | --- | --- |
| `brand.primary` | `#82442F` | 主按钮、选中标签、定位点选中、强调链接、Tab 选中 |
| `surface.canvas` | `#F7F5F5` | 非地图页面大背景 |
| `surface.card` | `#FFFFFF` | 搜索栏、列表组、弹层与表单 |
| `text.primary` | `#242329` | 标题、正文 |
| `text.secondary` | **[建议]** `#6F6D74` | 辅助信息、元数据 |
| `border.subtle` | `#E6E6E8` | 分隔线与非重点边框 |
| `state.danger` | **[建议]** `#B42318` | 错误、危险操作；不以品牌色替代 |
| `state.success` | **[建议]** `#237A57` | 保存完成与验证成功 |
| `scrim` | **[建议]** `rgba(20,20,25,.40)` | 唤出底部操作面板时遮罩 |

字号：页面标题 22～24px，普通列表主标题 15～16px，正文 14～16px，说明 12～13px；不强行锁死系统字体缩放。主按钮可在 40～48px 高范围验证点击体验，触控目标建议不小于 44×44px。间距以 4px 为基础单位；卡片通常 10～14px 圆角，搜索框与筛选胶囊可用全圆角。默认细分隔线代替厚重阴影；只有地图悬浮元素可用轻阴影以提高与底图的区分度。

**关键差异**：现存 `packages/design/tokens.json` 的 `default` 为 `editorial`，`minimal.accent` 为 `#903F59`；旧原生微信 `miniprogram/utils/theme.js` 同样如此，而 Taro 的 `apps/wechat/src/app.config.ts` 仍使用暖纸白窗口与 Tab。**必须作为第一批代码改造统一更新**。开发可复用现有 `minimal` ID，改掉其主色并设为默认；需要处理旧用户本地 `editorial` 偏好，避免默认迁移产生意外视觉切换。选择主题的用户设置是否继续保留为可选项，目前未定，首版只需保证默认一致。

## 3. 全局导航与状态

```text
地图       调酒         ＋         社区       我的
Tab        Tab         动作         Tab        Tab
```

- **[确认]** 四个主 Tab；`＋` 是全局动作，不作为第五个可选 Tab。微信 Taro 可以用自定义 TabBar 或独立浮动按钮 + 四个真实页面，但必须真机核对页面栈与安全区。
- **[建议]** 点击 `＋` 显示简短底部动作菜单：**记一杯酒（优先）／记一次探店／发布图文**；根据上下文追加「推荐新酒吧」「写酒吧评价」「分享调酒作品」，不能堆一个九宫格。
- **[未定]** 与旧版五项菜单的最终合并方案；不得误将「记一杯酒」实现为「公开发布」。
- 从任何 Tab 点击 `＋`，取消后返回原 Tab、原搜索条件、原滚动位置；输入进行中时不丢草稿。
- 主导向按钮只保留一项；例如详情面板的「查看详情」或「记录一次」，其他操作用次级按钮。Tab 字体、图标尺寸和选中样式全端一致。
- 弹层遮罩触控、安全区、键盘遮挡、返回手势、无障碍标识必须有明确行为。

## 4. 地图首页（核心样板）

### 4.1 初始布局

```text
┌──────────────────────────────┐
│  搜索酒吧、商圈、关键词   [头像] │  ← 顶部悬浮白色搜索栏
│ [鸡尾酒吧] [营业中] [禁烟] [筛选] │  ← 横向条件胶囊
│                              │
│      真实地图 & 酒吧标记       │
│                         [定位]│
│                              │
│  ┌────────────────────────┐  │
│  │ ── 可拖动把手          │  │
│  │ 附近酒吧 / 地图内的店   │  │  ← 底部信息面板
│  └────────────────────────┘  │
├──────────────────────────────┤
│ 地图  调酒     ＋   社区   我的 │
└──────────────────────────────┘
```

- 搜索栏可搜索名称、关键词和商圈；输入有加载/无结果/错误重试状态。地图和列表共享筛选状态。
- 筛选胶囊：客观字段（营业状态、类型、价格、是否禁烟等）与主观氛围/场景标签分开表达；字段缺失显示未知，不把未知判为「否」或「正在营业」。
- 酒吧位置不可靠时不显示虚假的精确标记；可保留在待核实资料中，不能生成到此导航。
- 地图数据与地点卡片要有选中联动；选中点突出、面板跟随更新；点击地图空白区域返回未选中状态的行为**[建议]**。
- 定位需用户授权；不授权仍可通过输入城市/商圈和手动地图操作浏览。初次定位失败、地图 SDK 失败和网络异常应独立提示。
- **[未定]** 底部面板在首次打开时默认小幅露出附近列表、半屏还是隐藏。**[建议的 Alpha 原型]** 显示 1～2 行附近预览，地图优先；真实数据不足时不要伪造附近酒吧。

### 4.2 地点选中与面板三态

| 状态 | 主要内容 | 触发行为 |
| --- | --- | --- |
| S0 地图浏览 | 搜索/筛选、地图、底部少量预览（建议） | 首次进入、关闭地点 |
| S1 选中酒吧 | 店名、类型、简短特色/状态、缩略图、查看详情、想去、记录一次/导航 | 点击标记或列表项 |
| S2 展开详情 | 酒吧介绍、核实的地址与时间、酒单、公开照片/体验、外部真实入口 | 上拉面板或「查看详情」 |

S1 的操作需控制数量：**建议**首屏「查看详情」「想去」和「路线/记一次」在空间允许时展示；空间不足则把次级操作放入更多菜单。是否在面板中展开全部详情、或进入独立酒吧详情页，取决于微信地图原生组件与层级表现、图片长页性能、返回栈测试；允许采用 S1 预览 + 独立详情页的稳健落地方式，视觉仍按 Google Maps 式层级。

**需要核对的实现风险**：微信原生 `map` 组件与自定义弹层层级、`cover-view`、滚动/拖拽冲突、`scroll-view` 吸附、`safe-area` 与键盘。以真机支持优先于「必须实现完整手势」，提供「展开/收起」显式控件作为替代。

### 4.3 地图与列表切换

「查看列表」进入与地图同步的全量结果，保留当前城市/范围/筛选。结果卡使用酒吧名、位置/商圈、可靠时效信息、标签、封面；**不能虚构距离、评分、今日营业状态和实时空位**。点击列表项既可返回选中地图状态，也可直接进详情，但返回要保持原结果顺序和筛选。

### 4.4 酒吧详情内容顺序（建议）

1. 店名、真实照片或稳定占位、已核实类型/商圈、来源与更新时间。
2. 主操作：想去/收藏、导航/复制地址、私人记录本次到访；外部预订入口仅在已核实可用时出现。
3. 地址、营业时间与是否营业（数据缺失不能显示「营业中」）、联系方式。
4. 结构化酒单（品名、价格、更新时间、可能关联的酒款；未知则不关联）。
5. 主观体验标签与公开评价/照片，明确区分广告和普通内容。
6. 基础活动（存在且可信时），不假装平台站内完成预约、支付。

## 5. 「调酒」页面

- 顶部搜索栏优先，下面以酒款/基酒/材料/口味分类筛选；不要在首屏放大幅装饰性海报。
- 搜索结果默认按酒款归集；酒款详情列出多个配方版本，作者、来源、毫升/盎司、做法、出品量、难度等按真实数据展示。
- 「收藏配方」「开始调制」「记录这次制作」语义分离。仅按用户动作生成私人记录，不因为查看或收藏自动写入日记。
- 同款/不同版本的评价属于不同实体；酒款主页汇总不伪装成独立酒款评分。
- 步骤卡宜采用阅读友好的分段编号；可选的原料库存、杯型容量调整、风味推荐作为增强功能，不应阻塞基础配方查询。
- 没有原图的配方可以用简单统一占位图，不使用大量随机渐变或不明来源的酒款照片。

## 6. 「社区」页面

- **[确认]** 手机双列瀑布流，容器增宽时三/四列；真实照片与标题是视觉重点，不大量叠加装饰背景。
- 卡片：封面、简短标题、作者、必要互动；无图文字帖也有稳定布局；广告显著标记。
- 点击卡片进入帖子详情查看全文、图片、评论/回复、分享。加载更多、空状态、图片失败重试、无障碍顺序必须设计。
- 私人日记绝不出现在公开社区源中；用户主动分享时创建独立公共对象并预览展示信息，不默认泄露精确位置与私密关联。
- 不先追求个性化流量推荐、连续签到或大量标签，优先验证真实互动与内容质量。

## 7. 「我的」与个人饮酒日记

- 个人资料/账号状态、四组轻量功能入口：「饮酒日记」「酒吧足迹」「我的酒款」「收藏」；这些是**建议布局**，用户未最终选择首页直接展示时间轴还是功能入口式。
- 时间轴主视图按饮用日期排序；可以看到一杯酒、一段探店经历和关联的多杯记录，不强制所有条目都上传照片。
- 酒款档案聚合同一款不同次数的独立记录，能按地点、日期回查；未知酒款允许作为个人自由名称存在。
- 「我的酒吧足迹」是私人经历的另一种筛选视图；公开个人主页只能展示主动发布的内容。
- 日历/照片墙/高级筛选属于后续增强，不以假占位制造已上线的错觉。
- 开发与同步状态应只展示正常用户能理解的内容（如最近同步、离线待同步），不暴露 API URL、开发令牌或服务器参数。

## 8. 快速私人记录 UI

```text
＋ → 记一杯酒 → [选现有酒款 或 自由输入酒名]
              → [可选：照片/备注/日期/场景]
              → [保存到我的日记]（**默认私人**）
              → [继续完善] / [返回]
```

- 表单可以非常短：先能保存再完善。必填条件尚需研发与产品裁定，不应臆造「必须评价/定位/照片」。
- 酒吧饮用可选酒吧、酒单名称、价格；在家调酒可选配方版本、用量、制作心得；均不必填。
- 「记一次探店」可先选酒吧，也允许非地图选择和手动补记；在一次经历下逐杯添加，或后来从已有记录里关联多杯。
- 不按同一天、同地、同酒名自动创建关联；不因记录了酒吧和星级便推送至正式公开评价。
- 保存、取消、离开编辑、弱网失败、重复点击、断网恢复与照片上传失败应有明确交互文案和草稿保护。
- 单独「发布到社区」应在私有记录完成后独立触发，预览公开范围；此流程具体关联/快照规则仍待裁定。

## 9. 标准组件（先做最小集合）

| 组件 | 必需状态 | 用于 |
| --- | --- | --- |
| `SearchBar` | 默认/输入/加载/无结果/错误 | 地图、调酒、记录关联 |
| `FilterChip` | 默认/选中/禁用 | 地图、酒款筛选 |
| `VenueMarker` | 普通/选中/聚合/隐藏 | 地图 |
| `VenuePreview` | 未选中/选中/展开/不可定位 | 地图底部面板 |
| `VenueListItem` | 图/无图/数据未知 | 地图列表 |
| `BottomActionSheet` | 打开/关闭/登录引导 | 全局「＋」 |
| `DrinkEntryCard` | 私人/草稿/同步中/出错 | 日记时间轴 |
| `CocktailCard` | 知识库已匹配/用户自定义 | 调酒、关联 |
| `PostCard` | 图片/无图/广告/审核状态 | 社区 |
| `EmptyState` | 无数据/筛选空/权限拒绝/断网 | 全局 |
| `StatusLabel` | 私人/公开/待审/未知来源 | 发布/资料详情 |

色彩不是唯一状态信号；图标需要文本或无障碍标签。小程序触控目标与系统字体放大下不得互相覆盖。

## 10. 设计验收清单（代码实现后验收，不是目前已通过）

- [ ] A 目标背景 `#F7F5F5`、品牌强调 `#82442F` 在四个 Tab、搜索/弹层/按钮中一致；无 `#903F59` 误用于目标 A。
- [ ] 地图页不被过多卡片挡住，选中地点和展开内容的层次清晰。
- [ ] 定位拒绝、无坐标地点、未知营业/价格、无结果和弱网状态不误导。
- [ ] 地图与列表的搜索筛选状态一致，返回后仍保留。
- [ ] 中央「＋」不是第五个 Tab；取消不丢原页面状态。
- [ ] 保存一杯酒与发布社区内容为两个明确操作；私人记录不公开。
- [ ] 每次饮用独立留存，同款归集，不依赖社区和评分。
- [ ] 社区双列卡片不因为无图、长图、异步加载出现极端跳动。
- [ ] 真机测试地图覆盖层、拖动面板、键盘、安全区、导航返回、字体放大和点击区域。
- [ ] 微信小程序不使用来自 Google 的地图瓦片、商标或缺少许可的图片素材。
