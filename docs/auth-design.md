# 酒迹 · 正式账号与跨端身份方案（设计稿）

状态：**PD-006 产品原则已确认；服务端身份系统尚待开发。** 不要把当前 Sites 测试设备令牌、微信本机昵称或可浏览公开接口当作正式用户账号。

## 产品目标

- 微信小程序优先提供便捷的微信登录；同时保留**手机号注册、手机号登录与账号找回**，让非微信用户也可以使用。
- 第三方登录渠道统一绑定至酒迹内部账户，并支持用户主动发起的安全账号合并。具体第三方平台（如适用的 Apple 等）与各平台登录按钮需要单独确认、满足平台要求。
- 游客只能查看公开资料；收藏、草稿、帖子、评论等个人操作必须先完成登录（见 PD-003）。
- 用户不会看到 API、Cloudflare、D1、R2、设备令牌等开发配置。

## 登录流程

### 微信快捷登录

1. 用户主动点击“微信登录”。小程序调用 `wx.login` 获取一次性凭证。
2. 由酒迹服务端向微信完成登录凭证校验，获取对应的微信身份标识，在 `auth_identities` 中查找绑定的 `user_id`。
3. 已绑定则创建安全会话并登录；未绑定按注册与绑定规则引导创建酒迹账户，或验证后关联已有手机号账户。**不因手机号匹配文本就直接合并账号**。
4. 如需关联手机号，通过微信平台提供的 `getPhoneNumber` 授权交互，由用户主动授权、服务端用专门的手机号凭证换取手机号。微信允许且服务端核验成功时，可免去额外重复短信验证码。
5. 用户拒绝手机号授权、未满足接口资格、失败或触发风控时仍应提供正常的手机号验证流程；微信身份登录与获取手机号是不同的授权步骤。

参考： [微信小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html) 、[微信获取手机号](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)。上线前重新验证平台接入资质、权限、收费和当前 API。

### 手机号注册与登录

- 用户可选择手机号注册/登录；通过服务端发起一次性短信验证码、设置有效期与频率限制并核验手机号归属。
- 是否支持额外密码登录、邮箱找回、手机国际区号覆盖等，保持为独立待确认选项；**不能把短信接口已开发写成已完成**。
- 手机号已绑定账号时进入登录或验证后的绑定流程，不自动创建重复账号。
- 不将短信码、完整手机号或其他登录凭据记录在公开日志。

### 第三方账户绑定与合并

- 在“我的 → 账号与安全”中查看已绑定的登录方式；用户主动发起绑定/解绑，并确认当前账号身份。
- 新第三方身份：完成第三方授权，确认尚未被其他用户绑定后与当前 `user_id` 关联。
- 已被其他账号使用：要求用户再次验证另一个账号的控制权，再展示数据合并预览和明确的二次确认。
- 合并过程必须具备事务性和审计日志；收藏可去重合并，个人帖子/配方保留原记录与责任主体，冲突项可人工处理。
- 商家身份、审计记录、审核处罚、订阅或其他经济权益需要独立核对；不可通过账号合并转移/消除风控和经营主体限制。
- 取消绑定不能使账号失去最后一种可用登录方式；安全风险高的操作需重新验证。
- 未经用户明确确认，不按“手机号相同、昵称相同、头像相同”等简单特征自动合并。

## 参考数据模型（待数据库迁移设计）

```text
users(id, state, created_at, updated_at)
auth_identities(id, user_id, provider, provider_subject, verified_at, bound_at)
verified_phones(id, user_id, phone_normalized_encrypted, verified_at)
sessions(id, user_id, issued_at, expires_at, revoked_at)
account_merge_requests(id, source_user_id, target_user_id, status, authorized_at, completed_at)
auth_audit(id, actor_user_id, event_type, subject_id, created_at)
```

约束：身份提供方的唯一主体在一个时点最多绑定到一个活跃酒迹账号；用户 ID 为所有端的统一私有数据归属键；敏感字段最小化收集和保护；迁移、解绑、注销均保持数据隔离与可追溯。

## 建议服务端能力（草案；尚未部署）

```text
POST /v1/auth/wechat/login
POST /v1/auth/wechat/phone
POST /v1/auth/phone/send-code
POST /v1/auth/phone/verify
GET  /v1/me
GET  /v1/me/identities
POST /v1/me/identities/bind
POST /v1/me/identities/merge/preview
POST /v1/me/identities/merge/confirm
POST /v1/auth/logout
```

这些只是待设计的接口路径，不能与当前已部署的 `/v1/health`、`/v1/sync` 混淆。正式 API 必须支持独立登录会话与权限控制，业务端不得共用管理后台所有者令牌。

## 首个公开测试版验收要求

1. 未登录用户只能浏览，点击收藏、发帖、配方保存时跳转登录；取消操作可返回原页面。
2. 微信快捷登录成功；微信授权手机号的成功/拒绝/失败均能正确处理；不强迫以授权手机号代替其他注册路径。
3. 没有微信也能用手机号注册和登录，并可后续绑定微信。
4. 同一已验证账号在至少两种客户端登录后可同步私人收藏及内容；不同账号互不可见。
5. 重复绑定冲突有明确提示；合并必须验证两端控制权，经过用户确认且不可通过合并逃避封禁。
6. 注销、解绑、令牌过期与设备退出行为安全；个人信息不泄露到匿名同步接口。
7. 实现前与已上线 API 完成联合调试，并记录各端真机验收结果。
